Summary

An analyst who ships the whole chain

Four years turning messy source systems into reporting people actually run their week on — SAP extracts, healthcare referral data, student cohorts, warehouse telemetry.

Most of my work starts where the data is still wrong. I write the SQL and the Python that cleans and validates it, model it into something a BI tool can query without a fight, and then build the Power BI or Tableau layer stakeholders open every morning. At Vaibhav Laxmi that meant an ETL pipeline over a million SAP records with a data-quality framework in front of it; at Community Dreams Foundation it means Microsoft Fabric and OneLake feeding referral and rehabilitation dashboards for a care-coordination platform.

I care about the part most dashboards skip: whether the number is defensible. Every model I ship gets a baseline above it in the table — if a forecast can't beat "same weekday last week", it hasn't earned its place in a planning meeting. That habit is the through-line between the analyst work and the machine-learning work, and it's what the two projects below are built to demonstrate.

Warehouse Operations Monitoring System

Data engineering · Forecasting · NLP

Python · SQL · Star Schema · Scikit-learn · Tableau-Ready Extracts

A four-node fulfilment network end to end: a relational WMS extract and a document store of device telemetry and free-text shift notes, consolidated into one star schema behind an 11-rule data-quality gate. On top sit a workload forecast, an NLP layer over supervisor notes, and a single-file dashboard.

19.6%Lower forecast MAE than the planner's rule of thumb
5,964Rows quarantined by the DQ gate, none dropped silently
98.4%Accuracy routing shift notes to the right issue type

The result worth arguing about: unsupervised clustering of the notes was weak (ARI 0.15) while a supervised classifier hit 98.4%. The repo says so plainly and recommends bootstrapping a taxonomy with clustering, then shipping the classifier — reporting the honest number was more useful than burying it.

Book Recommendation & Reader Segmentation

Machine learning · Segmentation

Python · NumPy/SciPy · Scikit-learn · Collaborative Filtering · K-Means

Nine recommenders benchmarked on one split under one protocol — popularity and bias baselines, item-item and user-user neighbourhood CF, truncated SVD, regularized matrix factorization, a content model and a tuned hybrid — all implemented on NumPy and SciPy rather than called from a library. Plus five behavioral reader segments and a model predicting next-quarter reading volume.

0.613Best RMSE, 22% under the bias baseline
26.3%Hit rate at 10, against 10% for random
46.9%Lower engagement-model MAE than carry-forward

Two findings the README leads with rather than hides: truncated SVD — the version most people reach for first — loses to a neighbourhood model, while properly regularized matrix factorization wins outright; and the tuned hybrid improves NDCG by 0.0007, which is a component that did not earn its place.

Patient Referral & Rehabilitation Performance

Healthcare

Community Dreams Foundation · Power BI, Microsoft Fabric, OneLake, MySQL, Azure Data Studio, Python

The reporting layer for a care-coordination platform. Referrals arrive from multiple partner systems and have to be tracked from intake through placement and rehabilitation outcome — a funnel where a stall at any stage is a patient waiting. The dashboard replaced a set of manually assembled extracts with a Fabric-fed model that refreshes on schedule.

  • Referral funnelVolume and status by stage, with ageing on anything stuck — the view that turns a backlog into a work queue.
  • Rehab performanceOutcome and progress measures by program and provider, so variation between sites is visible rather than anecdotal.
  • Operational KPIsThe scorecard stakeholders open first: throughput, turnaround and the handful of measures leadership actually steers on.
  • Data qualityValidation results surfaced in the report itself, so a number nobody should trust is flagged rather than quietly wrong.

Course & Cohort Performance Tracker

Education

ASU Learning Enterprise · SQL, Tableau, Excel, HubSpot

Supporting 300+ students across three technical courses meant the grading queue and the support queue both needed to be visible. This tracker pulled assignment outcomes and HubSpot query volume into one place so faculty could see where a cohort was struggling while there was still term left to do something about it.

  • Score distributionMarks by assignment and cohort, with the spread shown rather than just the average — a mean of 78 hides two very different classes.
  • At-risk cohortsStudents trending below threshold across consecutive assignments, surfaced early rather than at final grades.
  • Grading throughputTurnaround time on the marking queue, so backlogs were managed instead of discovered.
  • Support demandHubSpot query volume by topic, which is the cleanest signal of which course material needs rewriting.
